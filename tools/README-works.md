# Works(制作実績)の運用ガイド

制作実績は **1案件 = 1フォルダ = 1ページ** で管理します。
案件を増やすときに触るのは「案件フォルダの中身」だけです。HTMLは手で書きません。

```
recolonge/
├─ works.html                          一覧ページ(WORKS:LIST の範囲だけ自動生成)
├─ works/001.html, 002.html …          詳細ページ(自動生成・1案件1ページ・ファイル名は番号)  ← 手で編集しない
├─ assets/works/<slug>/                ★案件フォルダ(ここだけ編集する)
│    ├─ work.json                         案件のデータ(文章・数値・タグ)
│    ├─ thumb.webp                        一覧・More Works 用のサムネイル
│    └─ 01.webp (02.webp …)               詳細ページの画像
└─ tools/
     ├─ works-order.txt                 表示順(1行1案件。上から表示)
     ├─ build_works.py                  生成スクリプト
     └─ templates/works-detail.html     詳細ページのひな形(デザイン変更はここ)
```

## 案件を追加する(3ステップ)

1. 雛形を作る
   ```
   python3 tools/build_works.py --new 2025-01-brand-product
   ```
   `assets/works/2025-01-brand-product/work.json` ができます。
   `work.json` の先頭に **番号(`no`)が自動で振られます**(既存の最大番号+1)。
   この番号が詳細ページのファイル名になります(`no: 10` → `works/010.html`)。
   **番号は公開後に変更しない**でください(URLが変わってリンク切れになります)。他の案件と重複もできません。
   フォルダ名(slug)は管理用の名前で、URLには出ません(半角英小文字・数字・ハイフンのみ。
   先頭に `年-月-` を付けるとフォルダが時系列に並んで見つけやすくなります)。

2. 画像を入れて `work.json` を書き換える(下の「work.json の項目」参照)

3. 生成する
   ```
   python3 tools/build_works.py
   ```
   詳細ページ・一覧ページ・「More Works」がまとめて更新されます。
   一覧ページの並びは **`tools/works-order.txt` の行の順** です(上から表示)。
   詳細ページ下の「他の実績」は、**日付の新しい順**(自分自身は除く)で上位3件が自動で出ます。
   新規追加(`--new`)した案件は、この一覧の先頭に自動で入ります。位置を変えたいときは行を移動してください。
   書き忘れた案件は末尾に並び、生成時に知らせます。
   入力ミス(画像がない、日付の形式違い等)は、生成前に日本語でエラー表示されます。
   書き込まずにチェックだけしたいときは `--check` を付けます。

## 案件を修正・削除する

- 修正: `work.json` や画像を直して、`python3 tools/build_works.py`。
- 削除: 案件フォルダごと削除して `python3 tools/build_works.py`。
  生成済みの `works/<番号>.html` も自動で削除され、一覧・More Works からも消えます。

## work.json の項目

| 項目 | 必須 | 内容 |
|---|---|---|
| `no` | ○ | 詳細ページの番号(ファイル名になる)。`--new` が自動で入れる。変更・重複不可 |
| `date` | ○ | `2025.1.31` または `2025.1`(日が不明なとき)。一覧の並び順と表示に使う |
| `client` | ○ | クライアント名(例: 日本コカ・コーラ) |
| `product` | | 商品・案件名(例: Coke)。なければ省略。題名は「client　product」になる |
| `title` | | 題名をそのまま指定したいとき(入れると client+product より優先。カード下段にも出る) |
| `thumb` | | 一覧用サムネのファイル名(16:9前後・横1200px以上を推奨)。**空なら「COMING SOON」の仮枠** |
| `images` | | 詳細ページの画像(配列)。**1枚なら静止表示、2枚以上なら横スクロールのカルーセル。空 `[]` なら「IMAGE COMING SOON」の仮枠** |
| `promotion` | ○ | プロモーション概要。**1行ずつ配列に分ける**(そのまま改行になる) |
| `details` | | 実施内容(例: `Instagramリール投稿、TikTok投稿`)。なければ表の行ごと出さない |
| `tags` | | 媒体タグの配列(`TikTok` `Instagram` `YouTube` `Event` は専用の色。それ以外は灰色)。なければ行ごと出さない |
| `stats` | ○ | 指標カード(下記)。2つ想定 |
| `client_full` | | 正式社名。入れるとタイトル下に表示し、Client欄もこちらになる |
| `description` | | 紹介文。入れると画像の下に表示 |
| `category` / `period` | | 入れると表の行が増える |

`images` の各要素は、ファイル名の文字列でも `{"file": "01.webp", "alt": "説明"}` でも書けます。

### stats(指標カード)の書き方

項目名は案件ごとに自由です(Views / Follower / Followers など)。

```json
{ "label": "Views",  "label_ja": "再生回数", "value": "7500000", "suffix": "over" },
{ "label": "ENG%",   "label_ja": "エンゲージメント率", "prefix": "AVG", "value": "5", "unit": "%" }
```

- `value` は **数字だけ**(カンマなし。小数は `6.8` のように)。表示はカンマ区切りと小数が自動。
- 表示の組み立て: `prefix` + 数値 + `unit` + `suffix`(例: `AVG 6.8%`、`7,500,000 over`)。

## 画像を後から入れる(仮枠の案件)

`thumb` と `images` を空のまま作った案件は、一覧・詳細・「他の実績」に灰色の仮枠が出ます。
画像をフォルダに入れて、`work.json` に `"thumb": "thumb.webp"`、`"images": ["01.webp"]` を書き、
`python3 tools/build_works.py` を実行すれば、仮枠が画像に置き換わります。

## 画像を軽くする(必ず実行)

画像は今後も増えるので、容量を抑えます。案件フォルダに png / jpg を置いたら、生成の前に次を実行してください。

```
pip3 install pillow            # 初回だけ
python3 tools/optimize_images.py            # 全案件(変換が必要なものだけ処理される。何度実行しても安全)
python3 tools/optimize_images.py <slug>     # 1案件だけ
python3 tools/optimize_images.py --dry-run  # 変更せず、何が変わるかだけ表示
```

- webp に変換し、横長は幅1600px・縦長は高さ1400px・thumb は幅1200pxまで縮小します。
- 1枚あたり約150KB以下になるよう画質を自動調整します(下限は画質60)。
- `work.json` 内のファイル名(`01.png` → `01.webp`)も自動で書き換えます。
- **変換元の png / jpg は削除されます。元画像は手元に残しておいてください。**
- 対象は `work.json` のある案件フォルダだけです(`assets/works/preview/` などには触れません)。

## スマホ画面キャプチャを使うとき

TikTok・Instagram の標準UI(ボタン・いいね数・ユーザー名・キャプション欄)が写り込んだ画像は、
UIを消してから案件フォルダに入れてください(動画内のテロップや商品は消さない)。

## 画像について

- 形式は webp(またはpng/jpg)。1枚あたり 200KB 前後までが目安です。
- 詳細画像は横長(16:9)が基本。縦長・横長が混ざっていても、複数枚のときは自動で見た目を整えます。
- 画像にタイトル帯など、ページ側で出している文字(案件名・日付)を焼き込まないでください。

## 公開時の設定(build_works.py の冒頭)

- `NOINDEX = True` … 現在は全詳細ページが検索エンジン非公開(noindex)です。
  公開するときに `False` にして再生成すると、全ページで一括で外れます。
- `MORE_COUNT = 3` … 詳細ページ下の「More Works」の表示件数。

## 触らないもの

- `works/*.html`(001.html など) … 生成物。直しても次回の生成で上書きされます。
- `works.html` の `WORKS:LIST:START 〜 END` の間 … 同上。それ以外の部分(ナビ・見た目)は通常どおり編集できます。
- デザインを変えたいとき: 詳細ページは `tools/templates/works-detail.html`、一覧は `works.html`(マーカー外)を編集して、再生成します。

## トップページ(index.html)のリール

トップのワークスリール(5枚)だけは、画像を埋め込んだ手作りの作りのため自動化していません(現在は 014 → 010 の最新5件)。
差し替えるときは `index.html` の次の3つを、同じ並びで入れ替えます。
- `PORTFOLIO` … 社名・表示名・`url`(`works/014.html` のように番号)
- `IMAGES` … 画像(base64。ローカルで開いたときもWebGLが読めるよう、ファイルではなく埋め込み)。案件の thumb.webp を幅1000px・約100KB以内にして埋め込む
- `IMAGE_ASPECT` … 各画像の 幅 / 高さ
